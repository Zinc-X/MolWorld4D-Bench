# MolWorld4D-Bench v0.3.0 validation

The final v0.3.0 implementation was replayed on the same ten LogicMD systems
used for v0.2.0 validation.

## Outcome

- requested cases: 10;
- successful cases: 10;
- failures: 0;
- common time grid: 1 ns for every case;
- resolved common horizon: 499 ns for every case;
- resampling factor: 1 for every trajectory;
- fixed compatibility state count: 6;
- kinetics estimable: 3/10 (`2A14`, `2UYQ`, and `3L3M`).

All scalar values shared with the v0.2.0 output have a maximum absolute
difference of zero. New v0.3.0 columns and tables record the resolved common
clock, comparison horizon, parameter conversion, and configuration inheritance.

## Compatibility decision

An intermediate build made adaptive state selection and automatic physical-time
controls the default for `full`. The ten-case replay showed that this changed the
benchmark definition and reduced MFPT estimability. That default was rolled back:

- `full` retains the v0.2.0 defaults for TICA/MSM/ACF/bootstrap, six states, and
  no implicit windows;
- `n_states: auto`, physical-time `*_ns` controls, and automatic windows remain
  available explicitly and in task-oriented profiles;
- exact common-grid harmonization and horizon auditing remain mandatory because
  they prevent invalid comparisons across different physical clocks.

The intermediate outputs are retained under descriptive `v0.3.0_pre_*`
directories and were not deleted.

## Final output

`v0.3.0_final/` contains the complete report and audit tables. In particular:

- `timebase_audit.csv` records input and common clocks, resampling factors, and
  horizon rounding;
- `parameter_resolution.csv` records requested physical times, resolved frame
  counts, realized times, and rounding errors;
- `analysis_resolution.json` freezes global/case/model configuration inheritance.
